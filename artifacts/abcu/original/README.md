# DSA-Analysis-and-Design
In this course project, the main problem I was trying to solve was building a system that could organize and display a list of Computer Science courses, along with their prerequisites. I needed the courses to be loaded from a file and then sorted and printed out in alphanumeric order. Part of the process was analyzing different data structures to figure out which one would work best for this function: a Vector, a Hash Table, and a Binary Search Tree. After comparing them, it made sense to use a BST because of how naturally it keeps things in order while still being quick to search through. To tackle the rest of the project, I kept in mind how important it is to pick the right structure when you need to store a bunch of things in a way that's efficient for both searching and sorting.

While working through the project, I definitely hit a few bumps. At one point, I was getting a ton of errors because of small mistakes, like a missing bracket or using the wrong variable name. It took some patience and a lot of double checking to catch those. I also found that slowing down and really reading through my code carefully helped a lot, especially when the error messages weren't super clear. Overall, working on this project really expanded the way I think about designing software. It made me realize that planning out your structure ahead of time, like thinking about how data should flow through your program, makes a huge difference. It’s not just about making the program work. It’s about making it work in a way that's clean, efficient, and easy to fix later. I also became a lot more mindful about writing code that's readable and organized, not just for myself, but thinking about how someone else (or future me) could easily understand and update it.
